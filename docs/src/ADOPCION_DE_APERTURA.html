Propósito. Reunir la definición de apertura del proyecto y una ruta práctica para preparar, entregar y adoptar Nexo Demo, con resultados y criterios verificables.

Nexo es una aplicación Android local desarrollada con Kotlin, Jetpack Compose, Room/SQLite y DataStore. Permite explorar saldo, movimientos, ahorro, transferencias QR, pagos simulados, tarjetas y preferencias.

Alcance educativo: todos los datos, saldos y comprobantes son ficticios. No existe conexión con bancos, backend financiero ni operación con dinero real.

1 . ACTA DE APERTURA

Definición del proyecto

Justificación y objetivo general

Ofrecer un entorno de aprendizaje que permita comprender flujos habituales de banca móvil y desarrollar una aplicación Android con persistencia local, validaciones de negocio y una interfaz adaptable.

Objetivos específicos

  • Demostrar acceso con credenciales educativas y biometría opcional.
  • Representar operaciones ficticias y conservarlas después de cerrar la aplicación.
  • Practicar transferencias, pagos, ahorro y lectura de QR con validación previa.
  • Entregar código, APK y documentación reproducible para clases y evaluación.

Alcance y entregables

Incluye una aplicación Android de un solo módulo, datos de demostración locales, pruebas unitarias, análisis estático, APK de depuración y manuales de instalación, uso, ejecución y adopción.

Quedan fuera del alcance las transacciones reales, el alta de clientes bancarios, la aprobación de préstamos, una plataforma iOS, la sincronización entre dispositivos y el despliegue de una banca de producción.

Roles propuestos para la apertura

Rol por asignarResponsabilidad

El calendario y el presupuesto no están establecidos en el repositorio. Deben acordarse según el entorno académico y la disponibilidad del equipo.

2 . VISIÓN INTEGRAL

Funciones y arquitectura

ÁreaComportamiento de la demostración
AccesoCredenciales demo y comprobación biométrica de Android, con alternativa por contraseña.
Inicio y movimientosSaldo, actividad reciente, ahorro y consulta de movimientos con búsqueda y filtros.
Transferencias y QRIngreso manual o lectura QR, revisión y confirmación; recepción mediante QR.
PagosServicios y créditos ficticios; calculadora educativa de cuota, intereses y total.
Perfil y tarjetasDatos ficticios y controles de tarjeta guardados localmente.
ConfiguraciónTema Sistema/Claro/Oscuro, biometría inicial, saldo visible, versión y restablecimiento confirmado.

Organización técnica

Interfaz Compose -> NexoViewModel -> NexoRepository -> Room / SQLite
Preferencias de usuario -> UserPreferencesRepository -> DataStore

La raíz Gradle es banca_movile/android-app y contiene el módulo :app. La navegación se gestiona con estado Compose. Las pantallas se organizan en acceso, inicio, Más, transferencias, QR, perfil, pagos y configuración.

Reglas y persistencia

  • Los importes bancarios se almacenan como enteros Long en COP. Las mutaciones de saldo y operaciones usan transacciones Room.
  • Las cuentas de transferencia admiten 6-20 dígitos; el valor permitido es COP 1-5.000.000 y no puede superar el saldo.
  • Los QR aceptados usan nexo://transfer o nexo://receive. Leerlos no confirma una operación.
  • Room usa nexo_demo.db, versión 1; los cambios de esquema requieren una estrategia de migración.
  • DataStore conserva tema, biometría inicial y visibilidad del saldo. Los datos iniciales bancarios se centralizan en domain/DemoData.kt.

La aplicación funciona localmente sin Internet. Conserva el bloqueo de capturas y las copias de seguridad desactivadas. La biometría es un acceso demo, no autenticación bancaria ni cifrado de la base.

3 . PLAN DE ADOPCIÓN

Preparar la puesta en marcha

Ruta propuesta: preparación -> verificación técnica -> piloto -> entrega -> seguimiento. Cada fase termina con una evidencia; las fechas se acuerdan durante la apertura.

FaseActividad y evidencia esperada
PreparaciónAsignar roles, elegir dispositivo y revisar requisitos. Evidencia: entorno disponible y calendario acordado.
Verificación técnicaSincronizar, probar, analizar y compilar. Evidencia: resultados de Gradle y APK generado.
Piloto guiadoInstalar y recorrer acceso, transferencias, pagos, preferencias y reinicio. Evidencia: lista de resultados e incidencias.
EntregaCompartir APK y documentación vigente. Evidencia: paquete identificado y aceptación registrada.
SeguimientoAtender dudas y reproducir fallos. Evidencia: registro de incidencias y correcciones verificadas.

Requisitos para desarrollo

  • Android Studio, Android SDK Platform 37 y JDK 17 o superior.
  • Windows y PowerShell para los comandos de esta guía; Gradle Wrapper incluido.
  • Internet en la primera sincronización para descargar dependencias.
  • Microsoft Edge para regenerar los PDF con el script del repositorio.

Requisitos para usuarios

Teléfono, tableta o emulador con Android 7.0 (API 24) o superior. La biometría es opcional; la cámara se necesita solo para leer QR. Para instalar el APK, Android puede pedir permiso de instalación desde la fuente utilizada.

Preparación en Android Studio

  1. Selecciona Open y abre banca_movile/android-app.
  2. Espera la sincronización de Gradle e instala SDK 37 si se solicita.
  3. Selecciona el JDK de Gradle en la configuración de Android Studio.
  4. Conecta el dispositivo o inicia un emulador; selecciona app y pulsa Run.

El JDK que ejecuta Gradle debe ser 17 o superior; la compatibilidad Java del código es 11. Son configuraciones distintas.

4 . ENTREGA E INSTALACIÓN

Crear y adoptar el APK

Verificación y generación

Desde PowerShell en banca_movile/android-app, ejecuta:

.\gradlew.bat clean :app:testDebugUnitTest :app:lintDebug :app:generarApkDemo

Para generar únicamente la entrega:

.\gradlew.bat :app:generarApkDemo

Comprueba BUILD SUCCESSFUL. El APK se copia a banca_movile/distribucion/Nexo-Demo.apk; el original queda en app/build/outputs/apk/debug/app-debug.apk. Usa firma de depuración y está destinado a clases y demostraciones.

Documentación que acompaña la entrega

  • GUIA_INSTALACION_APK.pdf: instalación y solución de problemas.
  • MANUAL_USUARIO_NEXO.pdf: funciones y operación educativa.
  • MANUAL_APK_EJECUCION_GITHUB.pdf: ejecución, compilación y publicación.
  • ADOPCION_DE_APERTURA.pdf: apertura, adopción y aceptación.
  • README.md y docs/GUIA_DESARROLLO.md: referencia del proyecto y guía técnica.

Tras modificar las fuentes HTML en docs/src, ejecuta desde la raíz del repositorio:

.\banca_movile\scripts\generar-documentos.ps1

Instalación y primer acceso

  1. Transfiere el APK al dispositivo, ábrelo y autoriza la fuente si Android lo solicita.
  2. Instala y abre Nexo Demo; después desactiva el permiso de instalación desde esa fuente.
  3. Entra con demo@nexo.com / Nexo2026 o la biometría compatible.
  4. Recorre Inicio, Movimientos y Más usando exclusivamente datos ficticios.

Para instalar desde el entorno de desarrollo:

adb install -r ".\app\build\outputs\apk\debug\app-debug.apk"
adb shell am start -n com.nexo.banca.demo/com.nexo.banca.MainActivity

Cerrar la apertura

Registrar el resultado de cada criterio como pendiente, conforme o incidencia, junto con fecha, dispositivo y responsable. Esta lista no acredita pruebas ya realizadas.

Criterio de aceptaciónEvidencia que debe registrarse
Calidad y entregaPruebas y lint sin fallos; APK generado; cuatro PDF legibles y coherentes con la versión entregada.
Apertura y accesoArranque desde el icono; acceso demo; cancelación biométrica permite usar contraseña sin bucle.
OperacionesTransferencia válida actualiza saldo e historial; cuenta o monto inválido se rechaza; pago confirmado se registra.
QR y persistenciaQR válido carga datos para revisión; cerrar y abrir conserva movimientos y preferencias.
Navegación y temaAccesos específicos abren su sección; regreso Tarjetas -> Perfil -> Configuración; temas y saldo inicial funcionan.
RestablecimientoCancelar conserva datos; confirmar restaura datos ficticios y preferencias predeterminadas.

Soporte y contingencias

Registrar pantalla, pasos, resultado esperado y observado, versión y dispositivo. Para problemas de SDK, JDK, Gradle, cámara o instalación, consultar GUIA_DESARROLLO.md y la guía de instalación. No usar capturas como requisito de evidencia porque están bloqueadas.

Una firma distinta puede exigir desinstalar y perder los datos locales. Antes del piloto, acordar si se conserva la instalación o se inicia una demostración nueva. Para reiniciar, usar Configuración -> Restablecer demostración y confirmar.
